# PROJECT MASTER

## Goal

Build a Windows automation service that ingests approved source material, verifies rights, creates and approves content, publishes through allowed official interfaces, preserves history, and cleans up safely. The implementation uses Python 3.13, Playwright, APScheduler, and a selected AI provider. Python 3.13 is the target because it is the only runtime installed on this host, as verified by `py -0p`, and the P1-P5 tests passed on Python 3.13.

## Required Functions (9 MUST)

1. Ingest source content from an explicit, allowed source.
2. Verify rights and permission before content processing.
3. Analyse content with the configured AI provider.
4. Generate captions and supporting metadata.
5. Require human approval before publishing in `approve` mode.
6. Publish only through allowed official interfaces.
7. Preserve an auditable history of jobs and actions.
8. Schedule work with APScheduler.
9. Clean up temporary artefacts and close browser sessions safely.

## Modules P1-P5

- **P1 — Project skeleton and documentation:** repository baseline, configuration, dependencies, dry-run entry point, and project records.
- **P2 — Ingest and rights check:** source adapters, allowlist enforcement, rights/permission evidence capture.
- **P3 — AI analysis and captioning:** Gemini provider integration, structured analysis, caption and metadata generation.
- **P4 — Approval and publishing:** approval workflow, official UI automation, permitted publish adapters, and audit records.
- **P5 — History, scheduling, and cleanup:** durable history, APScheduler orchestration, retries, cleanup, and operational reporting.

## Workflow

`Ingest -> Rights check -> AI analyse -> Caption -> Approve -> Publish -> History -> Cleanup`

The workflow must stop before publish when required rights, permission, or approval is absent.

## Safety Rules

- Use only official web interfaces; do not emulate or bypass private APIs unless separately approved and officially documented.
- Restrict navigation and automation to the allowed sites configured in `config.yaml`.
- Never bypass CAPTCHAs, bot detection, access controls, rate limits, or other anti-automation protections.
- Never remove a watermark or provenance marker to hide content origin.
- Process and publish only content with documented rights or permission.
- Never commit passwords, API keys, cookies, session tokens, or other secrets. Read secrets from environment variables.
- Do not automatically bypass a manual approval requirement.
- Fail closed when rights, provider, configuration, destination, or approval state is uncertain.

## Acceptance Criteria

- All P1 skeleton files exist and contain no secrets.
- `py -3.13 main.py --dry-run` loads `config.yaml` and prints `ready` without import errors.
- `config.yaml` contains the required allowlist, `approve` mode, schedule, and Gemini provider.
- Meta/Muse verification is recorded honestly with date and official source.
- Each later module has explicit scope and remains unimplemented until its own phase.
- Safety rules are enforced by design and documented for contributors.

## Meta/Muse API Verification

- **Status:** VERIFIED for Meta Model API inference only; UNVERIFIED for a Meta/Muse content-publishing API.
- **Verified on:** 2026-11-09.
- **Official sources:** [Meta Model API overview](https://dev.meta.ai/docs/overview), [Muse Spark documentation](https://dev.meta.ai/docs/muse-spark), [Meta AI Connectors](https://dev.meta.ai/products/connectors).
- **Finding:** Official documentation describes Meta Model API inference at `https://api.meta.ai/v1` and Muse model IDs including `muse-spark-1.1` and `muse-spark-1.3`. It does not describe a direct content-publishing API for TikTok or similar destinations. Meta AI Connectors are documented for exposing an external service into Meta AI, while publishing and discovery of those connectors remain future work.
- **Decision:** Do not implement a `MetaProvider` publishing connection and do not treat `api.meta.ai/v1` or `muse-spark-1.1` as a publishing interface. The optional provider configuration in `config.yaml` is disabled.
